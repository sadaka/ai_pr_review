Decisions that constrain new work

  • ADR-003 — one Tiger Cloud Postgres-compatible spine for memory/truth/time, not three separate databases; Redis stays queue/cache-only → see ai-pr-review-agent.html §2.2–2.4
  • M1-fix-1 — migration must explicitly CREATE EXTENSION timescaledb_toolkit (not just timescaledb/vector/vectorscale) because the continuous aggregates use percentile_agg/approx_percentile, which are toolkit functions — do not remove this line even though Tiger Cloud pre-bundles the extension
  • M2-dedup-ordering — the webhook handler claims the Redis dedup key (mark_seen) before enqueueing, not after: this is what prevents a crash between "enqueue" and "mark-seen" from letting a GitHub redelivery double-enqueue the same job. The tradeoff is a failed enqueue after a successful claim must roll the claim back (unclaim) or a legitimate redelivery gets silently swallowed until the 24h TTL — do not remove the rollback when touching this path.
  • M2-redis-timeouts — job_queue/queue.py builds ArqRedis directly instead of using arq.connections.create_pool, because create_pool only wires a connect timeout, not a per-command socket_timeout. Don't switch back to create_pool without re-adding an explicit command timeout.
  • M3-no-langgraph-checkpoint-redis — deliberately did NOT use the official langgraph-checkpoint-redis package; it requires a RediSearch module (via redisvl) that Upstash's free tier doesn't provide. orchestrator/redis_checkpointer.py is a hand-written minimal async saver against plain Redis instead — narrower scope (no blob/version-delta storage, no cross-thread listing), sufficient for crash-resume, not a general-purpose replacement.
  • M3-resume-input-is-None — LangGraphEngine.run MUST pass None (not {} or any other value) as the graph input when resuming an existing thread — LangGraph treats ANY non-None input as a fresh invocation and re-dispatches from START, re-running every node including ones that already completed. This was M3's actual L4-caught bug; do not regress it.
  • M4-llm-provider-openai — the specialists and the embedding retriever run on OpenAI (openai SDK, chat.completions.parse + embeddings.create(dimensions=256)), decided 2026-09-06. anthropic + voyageai remain in pyproject.toml but are unused / reserved — do not wire them or remove them without an explicit decision. If a provider switch is ever made: llm_client.py + base_agent.py move to the Anthropic SDK, and context_retriever.py embeddings move to Voyage (Anthropic has no embeddings API) — ~4 source + 2 test files, plus a full re-embed of code_chunks (embedding spaces are not interchangeable).
  • M4-agent-type-stamped-in-code — agent_type is NOT part of FindingDraft (what the LLM emits); it is stamped by Finding.from_draft(draft, agent_type=self.agent_type) from the agent's class attribute. Keeps an un-forgeable field (used for M5 aggregator dedup + HITL routing) out of reach of a prompt-injected diff. Do not "simplify" by asking the model for it.
  • M4-specialist-failure-is-empty-list — when the structured LLM call returns parsed is None (refusal / unparseable / length cut), SpecialistAgent.review() returns [], never raises — one specialist must not break the M3 parallel fan-out/join. Consequence: a persistently-failing agent is currently indistinguishable from a clean one until M6 emits llm.call outcomes to agent_events.
  • M5-aggregate-collaborators-injected — aggregate() in orchestrator/nodes.py takes github / truth_store / hitl as parameters typed against local Protocol classes, never importing integrations/ or hitl/. Enforces dependency_direction (inward toward core/) and lets the e2e fakes satisfy typing. Do not "simplify" to concrete imports.
  • M5-gate-formula — overall_confidence = arithmetic mean of surviving (post-dedup) findings' confidence, and 1.0 when there are zero findings. Auto-post iff overall_confidence >= 0.75 AND no CRITICAL. decide() checks CRITICAL first, unconditionally — a CRITICAL always ESCALATES regardless of score. Empty finding list → AUTO_POST with GitHub event="APPROVE"; non-empty AUTO_POST uses event="COMMENT".
  • M5-truth-lane-mapping — Finding→finding_records: title→summary, line→line_start and line_end (same value — a zero-width range), suggestion→NULL (contract has no such field). Lossy: a finding that conceptually spans multiple lines is flattened to a single line. finding_records has no unique constraint — a re-run of aggregate() past the idempotency guard would double-insert.
  • M5-idempotency-is-guard-not-lock — redelivery safety rests on upsert_review's ON CONFLICT (github_delivery_id) + an early-return when status != 'pending'. No row lock (SELECT … FOR UPDATE) and no crash-window protection between post_review and mark_posted. Safe only because no retrying caller exists yet — must be hardened when graph.py / the ARQ worker call aggregate().
  • M5-post-raw-finding-text — _render_review_body interpolates finding title/rationale raw into the GitHub review body. A crafted diff can inject @org/team mentions, #123 cross-links, or restyling markdown (not code execution — GitHub renders markdown, no HTML/script). Accepted for M5; sanitization deferred to the M8+ injection-guard milestone.
  • M6-observability-is-opt-in — SpecialistAgent.review(diff, *, review_id=None): with no review_id it takes the exact M4 path — no budget gate, no event emission (default events is a full-signature NullEventSink). Events + budget only engage when a caller threads a review_id through. Keeps the M4 unit tests and Tiger-less runs working unchanged. Do not make review_id required.
  • M6-budget-guard-before-anything — the injected budget guard's check() runs at the very top of review(), before the first span.start emit and before any LLM call. When it raises BudgetExceeded, nothing lands in agent_events for that agent — there is no "blocked" row (a possible future add). With a 4-agent fan-out over the cap, all 4 raise independently.
  • M6-budget-reads-raw-events — CostRepository.spend_today_usd() sums raw agent_events (ts >= date_trunc('day', now() AT TIME ZONE 'UTC') AT TIME ZONE 'UTC'), not the agent_health_1m continuous aggregate the spec names — the aggregate lags its refresh policy (~1 min) and can't see same-run costs. agent_health_1m stays the dashboard read path. Trade-off: a row scan vs a precomputed rollup — revisit with a short-window rollup/cache at high PR throughput.
  • M6-cost-is-approximate — economics/pricing.py holds a hand-maintained OpenAI per-1M-token price map (gpt-5.4-mini, gpt-5.4, embeddings) with a _DEFAULT fallback for unknown models (never raises). Figures are for cost attribution + the budget gate, not billing — verify against live pricing before trusting a number.
  • M6-dependency-direction — agents/base_agent.py imports observability (the one documented cross-cutting exception) but never economics/**: BudgetGuard is injected behind a local SupportsBudgetCheck Protocol. observability/events.py does import economics.pricing (a zero-import leaf) to stamp cost_usd — accepted, but a cycle risk if pricing ever grows imports.
