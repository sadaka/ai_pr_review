## Micro-plan · 2026-09-08

**User design decisions (2026-09-08) — all "recommended":** (1) M9 = eval only; reliability → M10, DX/CI-CD/drift → later. (2) blocking metric is deterministic (recall + false-positive-rate vs committed baseline); LLM-as-judge scores rationale quality as a separate non-blocking layer behind live creds. (3) golden-run e2e requires live creds + skips cleanly (mirrors `test_specialists_e2e.py`); scorer + regression-gate logic unit-tested deterministically with synthetic `Finding` lists. (4) 3 YAML golden cases in `backend/evaluation/golden/`.

**No `dependency_direction` change** — `evaluation → agents` edge already declared; `evaluation/` is a leaf (test/CI-only, nothing imports it).

**New dep:** `pyyaml` added to the `dev` dependency-group (eval is test/CI-only; YAML block scalars are far cleaner than JSON for embedded code + diffs).

**Files:**
- `backend/evaluation/__init__.py` — new package.
- `backend/evaluation/golden/*.yaml` — 3 cases:
  - `sql_injection_lookup.yaml` — the existing `EXISTING_DB_MODULE` + `VULNERABLE_DIFF` from `test_specialists_e2e.py`; `expected_findings`: security/`*inject*`/`app/db.py`/line≈13, tests/`*coverage*`, docs/`*docstring*`.
  - `missing_tests_and_docs.yaml` — a new pure-logic function (e.g. a `compute_discount`) added with no test and no docstring, no security issue; expects tests + docs findings, `expect_max_findings: {security: 0}`.
  - `benign_refactor.yaml` — rename a local var / extract a constant, behaviour identical; `expect_max_findings: {security: 0, tests: 0}` and total ≤ 1 — the false-positive guard.
- `backend/evaluation/golden_dataset.py`:
  - `ExpectedFinding(BaseModel)` — `agent_type: AgentType`, `file: str`, `line: int | None`, `line_tolerance: int = 3`, `category_contains: str | None`, `title_or_rationale_contains: str | None`.
  - `GoldenCase(BaseModel)` — `id`, `description`, `repo_context: list[RepoFile]` (path+content, seeded into `code_chunks`), `diff: str`, `expected_findings: list[ExpectedFinding]`, `expect_max_findings: dict[AgentType, int] = {}`.
  - `load_golden_cases(path: Path = <golden dir>) -> list[GoldenCase]` — parse every `*.yaml`.
- `backend/evaluation/scorer.py`:
  - `matches(expected: ExpectedFinding, f: Finding) -> bool` — `agent_type` eq AND `file` eq AND (`line` within `±line_tolerance` when both set, else ignored) AND substring checks (case-insensitive) when set.
  - `CaseScore(BaseModel)` — `case_id`, `recall: float`, `matched: int`, `expected: int`, `missed: list[str]`, `false_positives: int` (findings over `expect_max_findings` per agent), `findings_by_agent: dict[str,int]`.
  - `score_case(case, actual: list[Finding]) -> CaseScore` — greedy 1:1 match, recall = matched/expected (1.0 when `expected == 0`), FP = sum(max(0, count[agent] - cap)).
  - `SuiteScore(BaseModel)` — `mean_recall`, `total_false_positives`, `per_case: list[CaseScore]`.
  - `score_suite(pairs: list[tuple[GoldenCase, list[Finding]]]) -> SuiteScore`.
- `backend/evaluation/judge.py` (non-blocking layer):
  - `RationaleScore(BaseModel)` — `score: float (0..1)`, `reasoning: str` (structured output).
  - `LLMJudge` — `__init__(self, client: SupportsStructuredCompletion)` (reuse the M4 `llm_client` Protocol shape — no second client); `async score(self, finding: Finding, case: GoldenCase) -> RationaleScore`. Prompt: "given the diff and this finding, rate how well the rationale explains a real issue, 0–1." Used only in the live e2e, over matched findings; never on the blocking path.
- `backend/evaluation/regression_gate.py`:
  - `GateThresholds(BaseModel)` — `max_recall_drop: float = 0.05`, `max_fp_increase: int = 0`.
  - `Baseline(BaseModel)` — `mean_recall: float`, `total_false_positives: int`, `recorded_at: str`, `cases: list[str]`.
  - `GateReport(BaseModel)` — `passed: bool`, `reasons: list[str]`, `current: SuiteScore-summary`, `baseline: Baseline`.
  - `evaluate(suite: SuiteScore, baseline: Baseline, thresholds = GateThresholds()) -> GateReport` — fail if `baseline.mean_recall - suite.mean_recall > max_recall_drop` OR `suite.total_false_positives - baseline.total_false_positives > max_fp_increase`.
  - `load_baseline(path) / write_baseline(path, suite)` — `evaluation/baseline.json` (committed).
  - `__main__`: `python -m evaluation.regression_gate [--update-baseline]` — runs the **deterministic** part only? No — the gate needs real findings, which need live creds. CLI: if creds present, run the live suite + evaluate + `sys.exit(0/1)`; if `--update-baseline`, write and exit 0; if creds absent, print a skip notice and exit 0 (CI-without-secrets is not a failure — the unit tests cover the mechanics). Wiring into GitHub Actions = phase 18, deferred.
- `backend/evaluation/runner.py`:
  - `async run_suite(cases, *, pool, llm_client) -> SuiteScore` — for each case: seed `repo_context` into `code_chunks` (embed via `ContextRetriever`), build `DiffContext`, run all 4 specialists, `score_case`, always clean up the seeded rows (try/finally, `DELETE WHERE repo = $1`). Mirrors the `seeded_repo` fixture pattern exactly.
- `backend/tests/test_evaluation.py`:
  - `test_golden_recall_computed` (deterministic) — a `GoldenCase` expecting 2 findings; synthetic actual = 1 match + 1 miss + 1 unexpected security finding (cap 0) → `recall == 0.5`, `false_positives == 1`, `missed` names the right one.
  - `test_match_respects_line_tolerance` (deterministic) — expected line 10, tol 3: finding at 12 matches, at 15 doesn't; `file` mismatch never matches; `category_contains` enforced.
  - `test_regression_gate_blocks_on_drop` (deterministic) — baseline `mean_recall 0.90`, current `0.50` → `passed is False`, reason mentions recall.
  - `test_regression_gate_passes_at_baseline` (deterministic) — current == baseline (and FP equal) → `passed is True`.
  - `test_regression_gate_blocks_on_new_false_positive` (deterministic) — recall equal, `total_false_positives` baseline 0 → current 2 → `passed is False`.
  - `test_load_golden_cases_parses_three` (deterministic) — `load_golden_cases()` returns 3 well-formed `GoldenCase`, each with ≥1 `expected_findings` or a non-empty `expect_max_findings`.
  - `test_golden_suite_e2e` (live, skipif on `TIGER_DATABASE_URL` + `OPENAI_API_KEY`, `loop_scope="module"`) — `run_suite(load_golden_cases(), …)` → `SuiteScore`; assert `mean_recall >= 0.6` and the SQL-injection case specifically has its security finding matched; then `LLMJudge` scores the matched findings and asserts every `RationaleScore.score >= 0.4`. ## quiz-me · 2026-09-08

A flaky/expensive judge call could wedge the pipeline or flip pass/fail run-to-run; the deterministic scorer gives a reproducible gate, and `LLMJudge` scores rationale quality as a separate observability signal only.
- **Q2 — baseline is mean_recall 1.0; what happens if the security agent misses the SQL-injection finding (3-expected case)?** → *"Gate fails — ~0.11 mean-recall drop exceeds the 0.05 tolerance."* ✓ correct. That case → 2/3 recall, mean across 3 falls ~0.11 > `max_recall_drop=0.05` → `evaluate()` returns `passed=False`. Intended sensitivity; `--update-baseline` re-seeds on a deliberate change.
- **Q3 — how does the golden runner avoid polluting shared Tiger `code_chunks`?** → *"Unique per-run repo name + DELETE in a finally block."* ✓ correct. Each case seeds under `eval-golden/{id}-{uuid}`; `run_case` always `DELETE`s `WHERE repo=$1` in `finally`, even on failure — mirrors the `seeded_repo` fixture.
