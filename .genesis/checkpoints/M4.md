## Quiz-me · 2026-09-06
**Q1 (design) — Why the two-tier `FindingDraft` → `Finding` split instead of the LLM emitting `agent_type` directly?**
User first answered with the L4 maker/checker rationale (separate model generates vs. verifies — correct about *that*, but a different split). Clarified: the schema split keeps `agent_type` out of what the LLM produces because (a) the agent already knows its own identity, (b) it's a field the model can get wrong or have spoofed via a prompt-injected diff, and `agent_type` drives M5 aggregator dedup + HITL routing, (c) principle — LLM produces judgment, code stamps facts. User confirmed understanding.

**Q2 (edge case) — What happens when `message.parsed` is `None`?**
`review()` returns `[]` — treats refusal / unparseable output as "nothing to report", not a crash. Rationale: one specialist must not break the M3 parallel fan-out/join; "no findings" and "couldn't produce findings" collapse to the same safe outcome; conservative direction for a CI tool (missing comment > crashed check). Known gap: silent — indistinguishable from a genuinely clean agent until M6 emits `llm.call` outcomes to `agent_events`. User confirmed.

**Q3 (change impact) — What did `loop_scope="module"` fix?**
The live e2e test failed with `Future attached to a different loop`. Cause: `db_pool` / `retriever` / `seeded_repo` are `scope="module"` but pytest-asyncio's default loop is function-scoped; `asyncpg` pools bind to the loop alive at creation time, so the module pool was created on the first test's loop, which then closed. `loop_scope="module"` on the marker + async fixtures pins one loop for the whole file so fixture lifetime and loop lifetime match. Test-harness only — production runs one long-lived loop. User confirmed.

Verdict stands: **APPROVE**. All three Q+A logged.
