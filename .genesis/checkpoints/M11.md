# M11 — (scope TBD — see G0 design question)

## G0 · 2026-09-08
- **the fork in the road:** the `M11+` PLAN/DONE row lists roadmap phases 15/17/18/20 (governance / DX-prompt-playground / CI-CD-eval-gates / continuous-learning). **But** every milestone since M5 has carried forward the same structural debt: *"rewire `orchestrator/graph.py` to call `nodes.aggregate` + swap the stub specialists for the real M4 agents; build the ARQ `run_review` worker."* **The system does not run end to end.** `webhook_receiver` enqueues a `run_review` job (`job_queue/queue.py:154`) that **nothing consumes** — there is no `job_queue/arq_worker.py` (spec §4.2 module map: `job_queue/ = arq_worker`). `orchestrator/graph.py` still fans out to **stub** nodes (`{"status": "stub-complete"}`) and its `_aggregate` just counts agents. `orchestrator/nodes.py::aggregate` (the real M5 dedup→score→HITL-gate→post→truth-write) is **never called by the graph.** So: 4 real specialists exist and are tested (M4), the aggregator exists and is tested (M5), the observability/cost/budget spine exists (M6), the reliability layer exists (M10) — but they are not connected into a pipeline a webhook can actually drive.
- **wiki pages read:** [[wiki/index.md]], [[concepts/LangGraph-Orchestrator]] (the Send-API fan-out + Redis checkpointer — currently stub nodes), [[concepts/Grounded-Specialist-Agents]] (the 4 real agents M11 would wire in), [[concepts/Webhook-Ingress-and-Job-Queue]] (the enqueue side that has no consumer).
- **spec re-read:** §4.1 phase 4 gate ("LangGraph fans out to 4 nodes in parallel; checkpoints resume") — proven with stubs in M3; phase 8 ("4 specialists + contracts + aggregator produce one review") — M4/M5 proved the pieces but not through the graph. §4.2 module map: `job_queue/ = arq_worker` (**missing**), `orchestrator/ = graph, nodes, state, langgraph_engine` (`graph` is stub-only, no `state.py`). §4.1 phases 15/17/18/20 are all *polish on a working pipeline* — governance/audit queries, a prompt playground, CI eval gates, drift detection — none of them matter if a PR never actually gets reviewed.
- **codebase grep — what's missing for end-to-end:**
  - `job_queue/arq_worker.py` — **does not exist.** No `WorkerSettings`, no `run_review` function. `arq>=0.26` is a declared dep.
  - `integrations/github_client.py` — only `post_review`. **No method to fetch a PR diff** (`GET /repos/{o}/{n}/pulls/{k}` with `Accept: application/vnd.github.v3.diff`, or the files API). The worker needs the diff to build a `DiffContext`.
  - `orchestrator/graph.py` — `_make_specialist_node` returns a stub dict; `_dispatch_to_specialists` + `_aggregate` have no access to real agents / retriever / github / truth_store / hitl. Rewiring needs those dependencies injected into the graph build.
  - `orchestrator/state.py` — **does not exist** (`ReviewState` TypedDict is inline in `graph.py`).
  - `core/workflow_engine.py::WorkflowEngine.run` signature — `(initial_state, *, thread_id)`. Real specialists need clients/pools that can't be JSON state — they're injected at graph-*build* time, not passed as state. `LangGraphEngine.__init__(redis)` would grow to take the agent/retriever/github/truth_store/hitl deps.
  - `nodes.aggregate(...)` — takes `findings_by_agent: Sequence[Sequence[Finding]]` + `github` + `truth_store` + `hitl` + `events`. The graph's aggregator node would collect the 4 specialists' `Finding` lists off `specialist_results` and call this.
- **decisions that bind us:**
  - ADR-001 (`WorkflowEngine` hides LangGraph) — the worker must call `WorkflowEngine.run`, never LangGraph directly. Injecting real deps into `LangGraphEngine` is fine; leaking `langgraph` types past it is not.
  - `dependency_direction` — `job_queue → orchestrator` (declared), `orchestrator → agents` (declared), `orchestrator → integrations`/`hitl`? Currently `nodes.py` avoids importing `integrations`/`hitl` via local Protocols (M5). The graph rewiring must keep that — inject `github`/`truth_store`/`hitl` as Protocol-typed params, don't `import integrations` in `orchestrator/graph.py`.
  - `outbound_call_safety` — the new diff-fetch call on `github_client` needs the same self-contained timeout/retry/breaker the rest of that client has.
  - `single_data_spine` — the worker creates the asyncpg pool(s) + Redis; truth writes go through `TruthStore` (already M10-guarded).
  - `structured_output_only` — specialists already return `Finding`; the graph must carry `Finding` data (serialized through checkpoint state — `Finding` is a pydantic model, `.model_dump()` / re-validate at the aggregator node).
- **credentials:** none new — the worker uses `REDIS_URL`, `TIGER_DATABASE_URL`, `OPENAI_API_KEY`, and the M2 GitHub App creds, all already in `.env`. A live end-to-end test would need all of them (skipif).
- **scope tension / design question (surface to user — this is the whole G0):**
  - **Option A (recommended) — M11 = "wire the real end-to-end pipeline."** Build `job_queue/arq_worker.py` (`run_review`), add `github_client.get_pull_request_diff()`, rewire `orchestrator/graph.py` real specialist nodes + an aggregator node that calls `nodes.aggregate`, grow `LangGraphEngine` to take the injected deps, extract `orchestrator/state.py`. Demo: a fake-GitHub + fake-LLM (or live) end-to-end test that a `ReviewJob` in → the 4 real specialists run in the graph → `nodes.aggregate` runs → a review row + findings land in Tiger and `post_review` is called once. This closes the M5/M6 carry-forward debt and makes the system *actually work*. Bigger than a typical slice (~1.5 milestones of surface) but it's the critical path and nothing downstream matters without it.
  - **Option B — M11 = next roadmap phase (e.g. phase 18, CI/CD eval gates: wire the M9 `regression_gate` into a GitHub Actions workflow + prompt versioning).** Smaller, cleanly scoped, but builds more polish on top of a pipeline that still can't review a PR.
  - **Option C — split A: M11 = ARQ worker + diff-fetch + graph rewiring (mechanics, fake-driven tests); M12 = live end-to-end hardening + the observability `review_id` threading that M6 left unwired.**
- **verdict:** **UNBUILT** (both the pipeline wiring and every roadmap phase) → await the scope decision, then micro-plan + L1 BUILD.

## Micro-plan · 2026-09-08

**User scope decision (2026-09-08):** **Option A — M11 = wire the real end-to-end pipeline.** Blocking demo is fake-GitHub + fake-LLM; one live e2e behind the usual skipif.

**Freeze boundary (widened, user-approved):** `backend/job_queue/arq_worker.py` (new), `backend/orchestrator/{graph,state}.py` (rewire + extract), `backend/orchestrator/langgraph_engine.py` (inject deps), `backend/integrations/github_client.py` (add diff fetch), `backend/tests/test_pipeline_e2e.py` (new). `webhook_receiver` / `nodes.py` / `agents/**` untouched (nodes.aggregate is called as-is).

**Design spine:**
- Real deps enter the graph at **build time**, not as JSON state. `build_review_graph(deps: GraphDeps)` closes the specialist nodes over the 4 agent instances and the aggregator node over `github` / `truth_store` / `hitl` / `events` (all Protocol-typed — `graph.py` imports `agents.specialists` (declared edge) + reuses `nodes.py`'s `SupportsPostReview` / `SupportsTruthStore` / `SupportsHitlQueue` Protocols, so **no `orchestrator → integrations` / `orchestrator → hitl` import**).
- `initial_state` = `{repo_full_name, pr_number, delivery_id, diff_text, review_id}`. The worker does `TruthStore.upsert_review` **first** to get `review_id`, so specialists can run the M6 observability path (`agent.review(diff, review_id=review_id)` → span/tool/llm events land in `agent_events`) — this also closes M6's "review_id never threaded" carry-forward. `nodes.aggregate` re-`upsert_review`s (idempotent → returns the same row).
- `Finding`s cross the checkpoint boundary as `f.model_dump()` dicts on `specialist_results` (the `operator.add` reducer still merges the parallel writes); the aggregator node re-validates to `Finding` before calling `nodes.aggregate`.

**Files:**
- `backend/orchestrator/state.py` — extract `ReviewState` TypedDict from `graph.py`: `repo_full_name, pr_number, delivery_id, diff_text, review_id: str`, `specialist_results: Annotated[list[dict], operator.add]` (each `{"agent": str, "findings": list[dict]}`), `aggregated: dict | None`.
- `backend/orchestrator/graph.py` — replace the stubs:
  - `@dataclass GraphDeps` — `agents: Mapping[str, SpecialistAgent]` (keyed by agent name), `github: SupportsPostReview`, `truth_store: SupportsTruthStore`, `hitl: SupportsHitlQueue`, `events: SupportsEmit`, `threshold: float = DEFAULT_CONFIDENCE_THRESHOLD`.
  - `_make_specialist_node(name, deps)` → builds `DiffContext(repo_full_name, pr_number, diff_text)` from state, `findings = await deps.agents[name].review(diff, review_id=state["review_id"])`, returns `{"specialist_results": [{"agent": name, "findings": [f.model_dump() for f in findings]}]}`. Keeps the `test_hooks` escape hatch.
  - `_aggregate_node(state, config, deps)` → regroup `specialist_results` into `findings_by_agent: list[list[Finding]]` (re-validate dicts), call `await nodes.aggregate(repo_full_name=…, pr_number=…, delivery_id=…, findings_by_agent=…, github=deps.github, truth_store=deps.truth_store, hitl=deps.hitl, events=deps.events, threshold=deps.threshold)`, return `{"aggregated": {"review_id": r.review_id, "decision": r.decision.value, "overall_confidence": r.overall_confidence, "github_review_id": r.github_review_id, "findings": len(r.deduped_findings)}}`.
  - `build_review_graph(deps) -> StateGraph` — same fan-out shape as M3 (Send API + conditional edges), real nodes.
  - Keep the old `build_graph()` name as a thin alias? No — M3's `test_orchestrator.py` uses `build_graph` + stub behaviour. **Keep `build_graph()` (stubs) for the M3 orchestration-mechanics tests; add `build_review_graph(deps)` for the real pipeline.** The mechanics test proves checkpoint/resume without needing live agents; the new e2e proves the wiring. Documented in both.
- `backend/orchestrator/langgraph_engine.py` — `LangGraphEngine.__init__(self, redis, *, deps: GraphDeps | None = None)`: `build_review_graph(deps)` when `deps` given, else `build_graph()` (back-comp for the M3 tests). Rest unchanged (the `None`-means-resume logic stays).
- `backend/integrations/github_client.py` — extract `_send(method, path, *, headers, json) -> httpx.Response` (the breaker+retry loop, currently inline in `_request`); `_request` becomes `_send(...).json()`. New `async def get_pull_request_diff(self, *, repo_full_name, pr_number) -> str` → installation token, `_send("GET", f"/repos/{o}/{n}/pulls/{k}", headers={Accept: "application/vnd.github.v3.diff", …})`, return `resp.text`. Same breaker.
- `backend/job_queue/arq_worker.py` — new:
  - `async def run_review(ctx, job: dict) -> dict` — `ReviewJob.model_validate(job)`; `diff = await ctx["github"].get_pull_request_diff(repo_full_name=…, pr_number=…)`; `review = await ctx["truth_store"].upsert_review(repo=…, pr_number=…, delivery_id=…)`; short-circuit if `review.status != "pending"` (return prior); `final = await ctx["engine"].run({...,"review_id": review.id,"diff_text": diff}, thread_id=f"review:{job['delivery_id']}")`; return `final["aggregated"]`.

Stash on `ctx`; close on shutdown.
