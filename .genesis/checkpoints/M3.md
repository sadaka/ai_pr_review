## Quiz-me Q+A · 2026-09-04
1. **Design decision** — Why does resuming a crashed run require passing `None`, not `{}`?
   - User's first answer had the mapping backwards (thought `None` = "already executed", `{}` = "fresh request"). Corrected: `None` = no new input, resume pending tasks from the checkpoint; any non-`None` value (including an empty dict) = fresh input, dispatch from START regardless of its contents. User confirmed understanding.
2. **Edge case** — Is a mid-flight (started, not finished) node treated the same as a never-started one on resume?
   - Explained (user requested it): yes — `aput_writes` only fires after a node's coroutine actually returns, so "started but cancelled before returning" and "never started" both leave zero recorded write and both get re-run from scratch on resume. Only a node whose coroutine truly completed is skipped. User confirmed.
3. **Change impact** — What does inlining `channel_values` (vs. the official blob/version-delta scheme) trade away?
   - Explained: gives up space-efficient reuse of unchanged per-channel data and cheap historical time-travel across many checkpoints, in exchange for a much simpler saver. Acceptable for M3 because state is small and runs are short; flagged as worth revisiting once M4 puts real LLM findings into state. User confirmed.
- verdict: APPROVE stands. Q+A logged, milestone cleared to mark done.
