**Files:**

- `backend/api/app.py` — local `create_pool` (same asyncpg pattern, `command_timeout=10`); `create_api_app(pool) -> FastAPI` mounts the router; `build_default_app()` reads `TIGER_DATABASE_URL` (`pragma: no cover`).
- `backend/tests/test_reviews_api.py` — insert a review + 2 costed `agent_events`, `GET /api/reviews` via in-process ASGI, assert the row shows summed cost + confidence + status; cleanup.
- `frontend/package.json` (pinned `next`/`react`/`react-dom`, scripts dev/build/start), `next.config.mjs`, `tsconfig.json`, `next-env.d.ts`, `.gitignore` (local), `README.md` (one line).
- `frontend/src/app/layout.tsx` — root `<html><body>`.
- `frontend/src/app/page.tsx` — `async` server component, `export const dynamic = "force-dynamic"`; `<h1>Reviews</h1>` + `<table>` (Review / Status / Cost / Confidence); empty-state row.
- `frontend/src/lib/api.ts` — `getReviews()` → `fetch(`${BACKEND_URL ?? "http://localhost:8000"}/api/reviews`, {cache:"no-store"})`, `try/catch → []`; `ReviewSummary` type.

## quiz-me · 2026-09-07
- **Q1 — one JOIN LATERAL sum vs N× `CostRepository.spend_for_review_usd`:** user — "there can be multiple entries for one review_id, so the lateral sums them once." Correct core idea (one pass sums all `agent_events` rows per review). Completed: it also avoids N+1 (1 round-trip vs 1+100), at the cost of duplicating the cost-sum logic in raw SQL rather than reusing `CostRepository` — the recorded G0 deviation.
- **Q2 — demo passes with the backend down:** user — "even when the server is not running a valid empty array is returned; it keeps the system from breaking." Correct. `getReviews()` try/catch → `[]`; the server component still SSR-renders `<h1>Reviews</h1>` + the table shell + a "No reviews yet" row; the curl demo only inspects SSR HTML.
- **Q3 — `asyncio.run()` nested-loop fix:** not answered by user. Answer: the pool moved into a FastAPI `lifespan` hook (opened on startup inside the running loop), which forced `create_reviews_router` to take a `get_pool: Callable[[], Pool]` resolved per-request instead of a pool bound at construction.
