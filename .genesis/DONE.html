1 · The Locked Spec (what we are building)

Cognitive job: Reclaim scarce senior-reviewer attention by automating the mechanical part of PR review. On every incoming pull request, run four specialist reasoners (security, quality, tests, docs) in parallel, each grounded in retrieved codebase context (never the diff alone), and surface only the findings worth a senior engineer's attention — selectivity, not maximal coverage.

Inputs: GitHub pull_request webhook (diff + metadata) + hybrid-retrieved codebase context (vector + full-text over code_chunks)  →  Outputs: a structured review posted to the PR — a list of Findings (agent_type, severity, category, file/line, confidence, rationale) — or entry into the human approval queue

Autonomy level: Confidence-weighted HITL gate, sitting at "human handles exceptions" on the 5-level spectrum, escalating to "human decides" on CRITICAL findings  |  Human-in-the-loop points: low-confidence approval queue; CRITICAL-finding escalation (always, regardless of confidence); developer dispute/feedback loop on posted findings

Failure tolerance: Degrade to slower-but-correct, never fast-but-wrong. Timeouts on every orchestrator node, retries with backoff, circuit breakers on dead services, idempotency at ingress (dedup on X-GitHub-Delivery), dedup across specialist findings at the aggregator  |  Trust boundary: GitHub App auth; HMAC-SHA256 webhook signature verification; posts as a bot to real (possibly private) repos; threat model must cover prompt injection via untrusted diff/file content

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master.
